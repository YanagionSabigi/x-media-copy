# X 图文复制与媒体下载

可直接加载的 Chrome / Edge Manifest V3 扩展（v1.0.0，Chromium 116+）。在 X 帖子操作栏最右侧保留一个小复制图标：复制原文、X 页面译文、静态原图和干净出处链接，复制成功后点赞，并通过浏览器下载视频或 GIF。

首次公开版 **1.0.0** 对应内部测试版 **0.6.3** 的功能，主要补充公开发布文档、许可证和上游对应源码。

所有转换都在扩展内完成，不安装电脑程序、不使用本机 FFmpeg、不上传到转换网站。压缩包内附带约 31 MiB 的 WASM 编码器，所以比旧版文字复制插件大。

## 安装或升级

**必须先解压 ZIP；不能直接点击 ZIP 或把 ZIP 拖进 Chrome 就完成安装。当前提供的是「已解压扩展」发布方式，没有发布到 Chrome Web Store。**

1. 在 [Releases](https://github.com/YanagionSabigi/x-media-copy/releases/latest) 下载 **`x-media-copy-1.0.0.zip`**。不要把 `upstream-sources` 源码归档当成安装包。
2. 右键 ZIP 选择「全部解压缩」，放到长期保留的文件夹，例如自己选定的扩展目录。不要只在压缩软件的临时预览中打开文件。
3. 打开 `chrome://extensions/`（Edge 使用 `edge://extensions/`），启用「开发者模式」。
4. 点击「加载已解压的扩展程序」，选择**直接包含 `manifest.json` 的文件夹**。若解压后有双层目录，进入包含这个文件的内层。
5. 刷新已经打开的 X 页面，然后使用帖子操作栏最右侧的复制按钮。

升级已有版本时，将原安装目录的文件替换为新版，在扩展卡片上点击「重新加载」，然后刷新 X。请避免同时启用旧版和新版。

**安装后必须保留解压目录，不能删除、移动或改名；浏览器会继续读取其中的 JS、WASM 和图标。原始 ZIP 可以删除。** 如果删除了目录，需要重新解压并重新加载扩展。此安装方式与 [Chrome 官方的 Load unpacked 流程](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked)一致。

Chrome 重载、更新或停用扩展会使已打开的 X 页面的旧脚本失效。v0.6.2 在复制前及后台通信前检查连接，失效时中止操作、停止旧页面扫描，并显示「刷新此页」按钮；不会只弹出 `Extension context invalidated.`。点击刷新后恢复连接，再点击复制。刷新仍由用户触发，避免打断正在编辑的帖子。首次从旧版升级也需要刷新 X，旧版脚本本身不会自动获得这项修复。

## 使用

- 复制图标位于评论、转帖、喜欢、转发等操作的最右侧，与原有按钮并排。按钮为 30 × 30 像素，图标为 18 × 18 像素，支持键盘聚焦和点击。
- 图片、视频、GIF、无附件帖子均提供按钮。没有正文的帖子也可复制出处链接。
- 点击后读取原文，必要时点击 X 的「显示翻译」并等待页面译文生成；没有翻译入口和译文时直接复制原文及链接。翻译入口存在但生成失败时提示重试。
- 原文和译文中的 hashtag 会去掉，优先识别页面标签链接；纯文本规则支持中文、日文、英文、数字、组合字符、全角井号，以及 `#foo-bar`、`#foo.bar`、`#作品・新作` 等常见带标点写法。仅包裹标签的空括号会清理；保留正文句子标点、普通 URL 的片段及 C#。有歧义的标点样式需要用实际原帖补充规则。
- 原文与中文译文之间保留一个空行；译文与图片组之间只换一行，图片之间不插入换行，图片组与出处链接之间只换一行。不添加标题，不存在的内容直接省略。粘贴软件仍可按窗口宽度自然折行。
- 帖子链接去掉全部分享查询参数、锚点及图片/视频页后缀，包括 `?=19`、`?=20`、`?s=20`、`?t=...`。
- **普通点击**：复制图文并点赞，随后提交该帖的媒体下载任务。**Ctrl+V** 粘贴；复制期间保持 X 标签页激活。
- 若遇到 `Document is not focused`，说明写入剪贴板时 X 页面失去焦点。回到 X 并点击页面空白处，再点复制；看到「已复制，可粘贴」后再切换标签页、打开扩展弹窗或聊天窗口。新版会直接显示中文操作提示，写入失败不会点赞或启动媒体下载。
- **Alt + 点击**：只取源语言原文，不带译文，也不等待生成译文；原图、干净出处链接、复制后点赞和视频/GIF 下载仍保留。若页面用译文替换了原文，会先恢复并读取真正原文，再还原页面显示。
- 已移除 Shift 专用操作和预览编辑框；按着 Shift 点击也按普通点击执行，Alt + Shift 按 Alt 执行。
- 自动点赞仅由成功复制触发；复制失败不会点赞。已点赞的帖子保持不变。
- 点赞操作只针对被复制的帖子，不点击引用帖或相邻帖子。复制后如果帖子已离开页面、按钮不可用，或两秒内未看到点赞状态，提示检查页面；已复制的文本仍可粘贴，不自动重试点赞。

## 原图与聊天粘贴

静态图只请求 X 提供的 `name=orig`，不再探测或比较 `4096x4096`；只处理当前帖子的附件，排除头像、表情、视频封面和引用卡片。读取失败会提示，不用缩略图冒充原图。这里的「原图」指 X 当前能提供的 orig 文件，无法恢复上传之前被平台处理掉的文件信息。

默认剪贴板提供纯文本和 HTML 两种表示。HTML 把原图字节内嵌在译文后、出处链接前，纯文本仍只有原文、译文、出处链接；Alt 模式省略译文。微信 / QQ 是否同时接收 HTML 内的文字和图片取决于客户端。

复制布局如下（图片为相邻的独立原图，没有额外空行）：

```text
源语言的帖子原文

grok 翻译后的中文
[图片][图片][图片]
原推链接（去掉分享参数）
```

页面可见时，自动为屏幕内停留至少 0.5 秒的静态图片预取 orig 文件；鼠标移入复制按钮或键盘聚焦也可提前预取。最近最多两帖，预取一次只读一张，点击复制的请求优先，正常复制仍最多三张并行。不会因为浏览帖子就写剪贴板、点赞、下载视频或转换 GIF。读取原图可与等待译文同时进行，剪贴板成功写入后立即提示可粘贴。

原图读取上限为每张 16 MiB、一次合计 24 MiB，解码上限为单张 1.2 亿像素，超过时提示失败，不静默压缩。读取失败不打开编辑框、不静默改成纯文字复制，可在原帖直接重试。

## 预取的内存与清理

- 只预取可见帖的静态附件；快速划过、屏幕外和隐藏页面不自动预取。预取只保存文件编码数据，不提前创建原尺寸位图；用户点击复制时才逐张检查图像，检查完立即关闭位图。
- 页面缓存预算为每个 X 标签页 **8 MiB**，扩展后台共享缓存预算为 **16 MiB**，均按 Base64 字符串每字符 2 字节保守计量，并按最近使用情况淘汰。页面最多保留两帖，后台最多 24 张；缓存最长 2 分钟，到期主动删除，无需下一次访问才清理。
- 这些是保留缓存的预算，并非 Chrome 进程总内存上限：N 个页面的编码缓存预算最多约为 `16 + 8×N MiB`，还存在消息、下载中数据、复制与图像解码的临时开销。浏览器自身、系统剪贴板和 GIF 转码分别使用内存。
- 自动预取的单张文件约限 3 MiB，单次预取返回数据也有 8 MiB 编码预算。大图或缓存放不下时跳过预取，点击复制时仍读取同一 orig 原图，不降画质或改用缩略图。预取尚未完成或缓存已清理时，复制仍可能需要等待网络。
- 切换到后台时暂停预取并释放页面所属缓存；导航离开、关闭标签页和扩展连接失效时取消所属原图请求、清除编码数据与定时器。后台通过页面连接断开和标签页关闭再清理；多个页面共享同图时，只在没有页面需要它时取消共享请求。迟到的旧请求不能重新填充新页面缓存。
- 所有扩展静态原图请求使用 [`cache: 'no-store'`](https://developer.mozilla.org/en-US/docs/Web/API/Request/cache)，不读写浏览器 HTTP 缓存；不把预取数据写进 downloads、chrome.storage、IndexedDB、Cache Storage 或本地文件。内存缓存随后台退出消失，不为保留缓存让后台常驻。
- 清除缓存引用后，何时回收进程内存由 Chrome 管理，任务管理器数字不保证立即下降。此功能不删除 X 网页自身已有的浏览器缓存，不清空系统剪贴板，也不删除用户主动下载的 MP4/GIF 文件。

## 视频与 GIF 下载

- 普通点击或 Alt + 点击后，视频取当前帖子的完整 MP4，多个已知版本按码率选最高档，避免下载单个分片或封面。
- X 的 GIF 通常以 MP4 提供；扩展下载完整源视频，在本地按原尺寸、完整时长转换为循环 `.gif`，然后通过浏览器下载。基于视频文件编码，不对网页播放器定时截图采样。GIF 有颜色和时间精度限制，不能恢复上传前原 GIF 的字节，也不能保证与 MP4 完全无损。
- GIF 采用两遍调色板处理，不静默缩尺寸、截短或降低帧率。首版上限：源文件 32 MiB、时长 60 秒、解码像素量 3 亿、输出 128 MiB、单次处理 180 秒。
- 点击浏览器工具栏的扩展图标查看任务状态、取消、重试，或在 GIF 转换失败后「下载原始 MP4」。备用文件明确以 `.mp4` 保存。下载完成后可直接拖入微信 / QQ。
- 已安装官方猫抓时，会尝试读取其资源列表并按当前媒体 ID 匹配，未安装猫抓也能使用自己的媒体解析。仅捕获到 HLS、找不到当前帖子的完整 MP4 时会提示，请播放该帖媒体后重试，或继续使用猫抓处理；本版不含通用 HLS 合并器。
- 下载完成以浏览器实际状态为准；媒体处理失败不撤销已复制文字或已成功的点赞。重新下载可在任务列表重试，无须再次点击点赞。扩展重新加载或浏览器重启会中断尚未提交的转换任务，回到原帖或任务列表重试。

## 权限与范围

支持 `x.com`、`twitter.com` 上的帖子。使用 `clipboardWrite`、`downloads`、`offscreen`、`storage` 权限，以及 `pbs.twimg.com` / `video.twimg.com` 媒体域名访问权限，不申请所有站点权限。

扩展在 X 页面加载开始时监听该页面自身的媒体响应，按帖子 ID 在页面内缓存媒体；后台任务状态保存于浏览器会话存储。媒体域名请求不主动携带登录凭据。不会把原文、译文或媒体上传给第三方服务器。WASM、JS、worker 和许可证都随包提供，转换器不从 CDN 加载代码，详见 `vendor/NOTICE.md`。

X 可能更改页面结构。如遇译文提取问题，可先展开页面译文再复制，或 Alt + 点击跳过译文。安装或更新后务必刷新 X，使媒体监听从页面开始加载时生效。真实登录 X 页面和微信 / QQ 客户端的最终粘贴表现尚未实测；已通过下列可控测试帖和真实扩展环境验证。

详细的数据与权限说明见 [PRIVACY.md](PRIVACY.md)。

## 验证与开发

自动回归覆盖文字、带标点标签、媒体元数据、原图 URL、引用排除、猫抓精确匹配、剪贴板、点赞、下载完成/失败、GIF 限制与转码参数。

隔离 Chrome 验证三张 2048×1024 原图字节保持一致、紧凑排版、Alt 省略译文且保留图片、Shift 普通复制、GIF 实际转码下载，以及扩展重载后点击刷新恢复复制。六类帖子验证按钮为 30×30 像素并排在操作栏末尾，复制后点赞不回退。预取测试中每张合成 PNG 约 1.35 MB、每次响应人为延迟 180 ms，图片准备时间约从 451 ms 降到 58 ms；这是可控测试结果，不是对真实网络延迟的承诺。

```powershell
npm ci --ignore-scripts
npm run vendor
npm test
node --check content.js
node --check core.js
node --check extractor.js
node --check clipboard.js
node tests/browser-check.cjs --native
node tests/extension-check.cjs --e2e
node tests/reload-check.cjs
node tests/prefetch-check.cjs
npm run package
```

测试使用隔离临时浏览器配置；扩展 E2E 用可控媒体响应，不依赖 X 账号。许可证及精确上游来源见 `vendor/NOTICE.md`。打包脚本只包含运行所需文件，排除 node_modules、测试数据和开发文档，并保留旧版发行压缩包。

对应源码归档由 `node scripts/prepare-upstream-sources.cjs` 生成，需要联网下载固定提交的公共源码；不执行上游源码。重新编译核心的优化单线程目标为上游 `make prd`，完整源树恢复和构建环境说明在对应源码归档 README 中。开发过程的截图、下载样本、浏览器配置和测试输出均不提交。
