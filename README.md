# X 图文复制与媒体下载

在 X 帖子的操作栏添加一个复制按钮，一次复制原文、X 译文、静态原图和出处链接，方便粘贴到聊天窗口或文档。帖子中的视频另存为 MP4，动图在浏览器内转换为 GIF 后下载。

**复制成功后会自动给原帖点赞**，已点赞的帖子保持原状态。

## 安装

需要 Chrome 116 或以上版本，以及能正常访问 X 的网络环境。

1. 从 [Releases](https://github.com/YanagionSabigi/x-media-copy/releases) 下载所需版本的插件 ZIP，或下载本仓库源码。插件包通常名为 `x-media-copy-<版本>.zip`。
2. 将 ZIP 解压到准备长期保留的文件夹。
3. 在 Chrome 地址栏输入 `chrome://extensions`，打开右上角的「开发者模式」。
4. 点击「加载已解压的扩展程序」，选择直接包含 `manifest.json` 的文件夹。
5. 打开或刷新 `https://x.com/`、`https://twitter.com/` 页面，在帖子的操作栏最右侧找到复制图标。

仓库已经附带 GIF 转换所需的 JS 和 WASM 文件。

更新时替换解压目录中的文件，在扩展管理页点击重新加载，然后刷新已经打开的 X 页面。

## 使用

将目标帖子滚动到可见位置，点击其操作栏最右侧的复制按钮。等待出现「已复制，可粘贴」，再切换到目标应用粘贴；不要在读取译文或原图时切走页面。

| 操作 | 复制结果 |
| --- | --- |
| 点击 | 原文、译文（如有）、各张静态原图、出处链接 |
| Alt + 点击 | 源语言原文、各张静态原图、出处链接，省略译文 |
| Shift + 点击 | 原文、译文（如有）、一张合成图、出处链接 |
| Alt + Shift + 点击 | 源语言原文、一张合成图、出处链接，省略译文 |

以上操作在复制成功后都会尝试点赞，并为帖子中的视频或动图提交下载任务。静态图片写入剪贴板，不会自动保存成图片文件。只有一张静态图或没有静态图时，Shift 操作按普通方式复制。

复制时会清理原文和译文中的话题标签，保留正文及规范化的帖子链接。引用卡片的内容不作为当前帖子的正文和附件一起复制。

### 译文与粘贴效果

译文来自 X 自身的翻译功能。扩展会尝试展开页面上的翻译或切回原文读取内容，不提供独立翻译服务；没有可用译文时不保证生成译文。若提示译文尚未生成，请先在 X 中展开翻译，再重新复制；只要原文时可用 Alt + 点击。

剪贴板同时包含纯文本和 HTML：纯文本包含原文、译文及出处，HTML 还包含静态图片。例如，原帖正文是 `A quiet afternoon. #photo`、译文是 `安静的午后。 #摄影`，纯文本结果为：

```text
A quiet afternoon.

安静的午后。
https://x.com/example/status/1234567890
```

图片是否随文字一起粘贴，取决于目标应用对 HTML 剪贴板的支持。微信、QQ 及其他编辑器可能有不同表现；纯文本输入框通常只接收文字和链接。GIF 和视频请从下载目录拖入聊天窗口。

### 多图合成

Shift + 点击适合把按顺序发布的切片图合回一张图片。扩展按附件顺序，结合尺寸和边缘相似度选择横排、竖排或矩形网格，输出原始尺寸的 PNG，不缩放或裁剪图片。

布局由程序推断，无法保证还原作者的原始排版，也不会自动重排附件。图片尺寸无法拼成完整矩形、超出处理上限或合成失败时，本次复制会报错；可改用普通点击，保留各张图片。

## 视频、GIF 与下载任务

普通视频使用捕获到的完整 MP4 地址下载；有多个 MP4 码率时，优先选择已取得的最高码率。X 的动图通常以 MP4 提供，扩展使用随包的 FFmpeg WASM 在本地转为循环 GIF，保持原尺寸。GIF 转换任务依次处理。

文件默认保存到浏览器下载目录的 `X` 子目录，命名为 `<帖子编号>_<序号>.mp4` 或 `.gif`。浏览器自己的下载设置可能要求另选保存位置。

点击浏览器工具栏中的扩展图标，可以查看任务进度、取消任务、重试失败或已取消的任务，以及打开已完成文件所在的文件夹。GIF 转换失败时，还可以选择「下载原始 MP4」。

若没有取得完整 MP4 地址，请先回到原帖播放媒体，再重新点击帖子上的复制按钮。插件可以尝试从本机已安装的 [猫抓 Cat Catch](https://github.com/xifangczy/cat-catch) 获取匹配资源；猫抓是可选补充。只有 HLS 流、没有完整 MP4 的资源，需要使用猫抓等工具另行处理。

## 常见问题与限制

| 情况 | 处理方法或说明 |
| --- | --- |
| 更新扩展后按钮失效，或提示连接已失效 | 确认扩展已启用，再刷新 X 页面；旧标签页中的脚本不会随扩展重载自动更新 |
| 提示页面未获得焦点，或切换窗口后未完成复制 | 回到 X，点击页面空白处后重试，等出现「已复制，可粘贴」再切换窗口 |
| 已复制，但提示未找到点赞按钮或无法确认点赞 | 可继续粘贴；到原帖检查点赞状态，扩展不会反复点击来尝试确认 |
| 原图读取或合图失败 | 本次不会继续写入剪贴板和点赞；检查网络或改用普通点击。普通点击仍受原图大小限制 |
| 视频没有下载，任务中提示没有 MP4 地址 | 先播放原帖媒体，再重新点击帖子上的复制按钮；弹窗重试无法凭空补齐缺失地址 |
| 后台重启后任务失败 | 在扩展弹窗重试；任务记录只在当前浏览器会话保存，已下载文件会留在下载目录 |
| 页面改版后无法识别正文、译文或按钮 | 本扩展依赖 X 的页面结构和媒体数据，可能需要随网站改版调整 |

为限制内存和处理时间，当前实现有以下上限：

- 静态图片：单张原图最多 16 MiB，一次读取原图合计最多 24 MiB；单张图片最多 1.2 亿像素。
- 合成图片：输入总面积最多 1.2 亿像素，单边最多 32767 像素，输出 PNG 最多 24 MiB。
- GIF：输入 MP4 最多 32 MiB、时长最多 60 秒、总解码量最多 3 亿像素；输出需小于 128 MiB，整个转换过程最多 180 秒。超过限制可选择下载原始 MP4。

GIF 使用调色板编码，颜色表现会受 GIF 格式限制；原尺寸转换也可能生成比 MP4 大得多的文件。

## 隐私与权限

图文提取、静态图合成和 GIF 转换在浏览器内完成，转换过程不上传媒体到转换网站。扩展不包含遥测或独立账号登录服务，也不会调用外部翻译 API。

为缩短等待时间，扩展会对可见帖子的静态原图做有限的预取，也会在复制按钮悬停或获得焦点时准备原图。预取因此可能在点击复制前访问 X 的图片服务器；缓存位于内存，有容量和过期限制，页面隐藏、导航或关闭时清理。视频和 GIF 不做这种自动原图预取。

| 权限或访问范围 | 用途 |
| --- | --- |
| `clipboardWrite` | 点击复制时写入文字、HTML 和静态图片 |
| `downloads` | 下载 MP4/GIF、跟踪状态、取消任务及显示文件位置 |
| `offscreen` | 运行本地 GIF 转换并保留供下载使用的临时文件地址 |
| `storage` | 在浏览器会话中保存媒体任务元数据 |
| `x.com`、`twitter.com` 页面脚本 | 添加按钮、提取帖子内容，以及读取页面已取得的媒体信息 |
| `pbs.twimg.com`、`video.twimg.com` 媒体域名 | 读取原图和视频资源 |

详细数据处理说明见 [PRIVACY.md](PRIVACY.md)。下载文件以及系统、聊天软件保存的剪贴板记录，分别由浏览器和对应软件管理。

## 开发与维护

使用原生 JavaScript、Chrome Manifest V3 和 FFmpeg WASM，没有前端打包步骤。CI 使用 Node.js 22；开发时需要 Node.js/npm，打包脚本还需要 PowerShell。

```sh
git clone https://github.com/YanagionSabigi/x-media-copy.git
cd x-media-copy
npm ci --ignore-scripts
npm test
```

随后按上面的步骤加载仓库目录即可。若修改了 `media.js`、`media-hook.js` 或需要重新准备 FFmpeg 资源，运行：

```sh
npm run vendor
npm test
```

`vendor` 命令会重新生成 `media-main.js`，复制锁定版本的 FFmpeg 文件，并将默认核心地址改为扩展内资源。

| 文件 | 职责 |
| --- | --- |
| `manifest.json` | 扩展入口、版本、权限和页面匹配范围 |
| `content.js` / `content.css` | 帖子按钮、复制流程、点赞和原图预取 |
| `extractor.js` / `core.js` / `clipboard.js` | 原文及译文提取、标签清理、出处格式和剪贴板写入 |
| `image-merge.js` | 多图布局推断与 PNG 合成 |
| `media.js` / `media-hook.js` / `media-bridge.js` | 媒体识别、页面响应捕获和脚本间数据传递 |
| `media-main.js` | 由脚本生成的页面主环境入口 |
| `background.js` | 原图请求、媒体下载队列和会话任务状态 |
| `offscreen.js` / `gif.js` / `vendor/` | 本地 GIF 转换与随包依赖 |
| `popup.html` / `popup.js` | 帮助及媒体任务管理 |
| `tests/` / `scripts/` | 自动化检查、依赖准备和发布打包 |

`npm test` 覆盖内容提取、剪贴板、点赞时序、图片缓存、合图布局、下载状态和依赖文件等行为。另有 `npm run test:extension` 和 `npm run test:merge` 浏览器检查；这两个脚本使用临时浏览器配置，当前 Chrome 路径写死为 Windows 默认安装路径，其他环境需先调整。

打包命令为 `npm run package`，会在仓库根目录生成 `x-media-copy-<版本>.zip`。若同名 ZIP 已存在，脚本会报错并保留旧包。打包采用文件白名单；发布前应完成 README 审阅、版本与声明核对、测试，以及上游对应源码准备，避免把本地测试功能与较旧发布包混为一谈。

反馈问题请使用 [Issues](https://github.com/YanagionSabigi/x-media-copy/issues)，注明扩展和浏览器版本、操作方式、提示信息及复现步骤。提交代码修改时，附上对应验证结果；涉及账号或私密内容时，不要附带 Cookie、令牌或私人帖子媒体。
